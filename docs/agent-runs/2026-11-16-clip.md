## 偵測

指令：`node scripts/plate-clip.mjs <out.json> [--anchor] [--min=0.25]`（dev server 在 127.0.0.1:3000；`--anchor` = 修前）。

方法：每區載入後手放在蓋面遠角（`lift`=0.55–1.0），取當下的狀態，在 CPU 上跑與著色器相同的頂點運動（`poseKit`），量單位為盤面單位。姿態共：`lying`（閒置躺著）、`lying-hand`（手在盤上、所有地都隆到全高、沒有部件站起）、以及每個群組 × 站起程度 0.14／0.4／0.7／1.0（該群組地全隆，其餘閒置）。量：
- 地：部件任一取樣點低於 `groundY` 的深度（網格與肢體取全部頂點；樹葉取 4×4 點，在**平的四邊形**上雙線性內插，不是取地面高度）。
- 部件 × 部件：一個群組的取樣點落在另一群組某個 mesh 部件的封閉體內（垂直射線奇偶），深度為到最近面的距離。同群組（塔的各層、樹與自己的葉與鶯）不比。偵測器自測：把每個部件當獨立群組時，Minami 抓到 13 對（鶯×松幹 3.76 等），確認它會報。

## 沒修的、限制

- 沒量：樹 × 樹（葉與肢體是薄片，奇偶法不適用）、樹上珊瑚葉 × 樹的細部、霞邊緣切部件的硬線（霞半透明，沒做）。這三類只由截圖粗看，沒看到問題；沒有數字。
- 同群組內部（塔各層屋簷互穿、塔壁 × 台基）設計上就接合，偵測刻意跳過。自測看到 pagoda-wall-0 × pagoda-base 1.58、wall-3 × lamp 1.03，是同群組，沒處理。
- 偵測是 CPU 鏡像，不是 GPU 讀回；與著色器一致性靠 `export-glb.js` 原有的鏡像與截圖對照，沒有逐像素比對。
- 構圖提案：無，沒有移動任何部件，沒有超過 12 單位的需求。
