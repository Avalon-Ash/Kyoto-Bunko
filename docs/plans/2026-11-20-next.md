## N5 換函卡頓（2026-11-20 深夜，使用者回報，分支 `claude/switch-1120`）

使用者：「現在換文箱還是會卡一下」，提議滑到邊緣時暗化、模糊做過場。主代理先量，再建議改法，使用者：「照這樣改」。決定寫在 ADR 0020。

**量法**（scratchpad 的 `switch.mjs`，沒提交）：自己開無頭 Chrome（ANGLE D3D11），首頁，第二次載入（著色器已進快取），等 4 秒讓鄰區預建完，對 `#scene` 送右方向鍵換函；記長任務、超過 50 ms 的 rAF 間隔、`renderedWard` 改變的時間（都從按鍵算起），結束時記兩個鄰盒預覽的 `data-ward`。

| | 換盤（約 466 ms） | 之後的長任務 |
|---|---|---|
| 改前（連續 4 次） | 79 ms 一次，其餘不卡 | 約 835 ms 處 383、283、600、338 ms |
| 改後（連續 4 次＋3 次） | 54–67 ms 一次，其餘不卡 | 約 1.4 秒處 58–77 ms（預建的分段），或沒有 |
| 改後，每 0.7 秒連換 | 走淡出淡入，換盤在約 190 ms，那時 136–454 ms（新區還沒預建完，盒子已淡出） | — |

**原因**：盒停穩 350 ms 後畫鄰盒預覽圖，用的是一般換區：鄰區還沒預建就同步建，而且一般換區會改排預建、淘汰快取，畫完 A 再畫 B、再換回本區的途中，B 和本區都可能被丟掉重建。

**改了什麼**：`three-renderer.js` 把 `activate` 拆出 `bind`，新增 `drawNeighbour`（只畫已預建並編譯完的鄰區，畫完綁回本區，不碰快取）；預建的鄰區編譯完時呼叫 `onReady`。`renderer.js` 新增 `drawNeighbour`，畫布尺寸與投影集中到 `size(f)`。`study.js` 畫預覽圖只走它；換函時預覽圖沒好就淡出淡入。

**驗證**：改後兩側預覽都補畫出來、是對的區（右京的兩側是南與西京）；把預覽 canvas 存成圖看過，是完整的西京盤。四項檢查：lint 0；validate `--strict` ERROR 0／WARN 0；test 155/155、17/17；build 0。蓋面矩陣：`plate-matrix.sh .shots/switch/{b,a} base mobile`（同一次開機、同一個 dev server），25 張 0 差異。改前那一輪腳本對「伏見日間」報了一次 WRONG（讀到的 data-ward 是南區夜間），比對仍是 0 差異；§8.17 的山科日間也一樣，是拍圖腳本的檢查偶爾讀早了，圖本身是對的。

**沒做**：使用者的實機上沒量；拖曳途中的畫面沒拍到（無頭 Chrome 的模擬拖曳沒觸發）。
