## 1. 這一包的語彙（都已在樣板兩區做出來，直接用）

樣板：中京（`nakagyo.js`）與伏見（`fushimi.js`）；建構函式在 `plate/doha.js`。規則的來源是 [`2026-11-16-doha.md`](2026-11-16-doha.md)，以下是定案的摘要；兩者不一致時以本檔為準。

| 東西 | 做法 | 出處 |
|---|---|---|
| **遠山** | 三到五座大而圓的山相疊成一個完整的山體；每座一道乾淨的圓弧（5–7 個控制點）；稜盛起、是最亮的一線，面是細粉往下暈，山腳化進地裡、沒有下緣；其中一座換成淡銀或青金加金線；山上沒有岩、沒有樹 | doha §10.7–10.9、§11.1、§15.2 |
| **岸與洲浜** | 沿著水或建築前緣的長帶，2–4 片相疊；輪廓是扇貝狀的波浪，沒有直線；面是濃梨子地（比地亮一階）；銀只當夾在金之間的細帶 | doha §11.2、ground-tone §3.2 |
| **霞** | 現有的 `suyari`。建築的後面與之間用霞隔開，建築從霞裡露出來；不要用地的碎片去墊建築 | doha §11.2 |
| **地** | 素的梨子地，最深的一層。留白至少四成，而且是連通的帶 | ground-tone §3 |
| **岩** | **這一包不動岩**。使用者指定岩先維持現狀；九區現有的岩（`rock()`）原樣保留、位置不變 | doha §18.2 |
| 包漿、屋頂、平嵌、樹貼地 | 已經全區生效，不用管，也不要改 | |

三條貫穿的規則（使用者的話）：
- **盤上的東西是正視的畫，不是俯瞰的實體。** 山、建築、樹都是立面的側影；不要把東西越做越扁、越像地形。
- **形狀不能複製貼上，要有手感。** 每一片、每一座山的輪廓逐一手寫在該區的構圖檔裡，不由模板加亂數產生。
- **每樣東西要答得出「它為什麼在這裡」。** 構圖服務該區的地標與意象，想「日本人會想看到什麼」。

## 2. 九區的構圖（主席設計；現況是各區構圖檔裡的 `hill`／`gardenGround`）

每區拆掉現有的 `hill()` 與 `gardenGround()`，改成下面寫的。建築、樹、鳥、狐、燈籠、池、流水、銀庭、小景等既有部件不刪、不改造型，位置可以微調（12 單位內）讓它們落在新的地上。掛在舊丘或舊台地上的小景（`on: '<舊 id>'`）要改掛到新的部件。

| 區 | 地標 | 現有的丘／台地 | 改成 |
|---|---|---|---|
| **東山** | 清水的懸造舞台、音羽山 | 丘三個（`otowa`、`slope`、`ridge-west`） | **音羽山**是舞台後面一座完整的遠山（四座山頭，最高的在本堂後方偏右），舞台從山腰挑出來。左上遠處一小段**西山**（兩三座低的山頭，淡）。舞台下方的坡改成一條**岸**，順著現有的音羽之水往左下流。舞台底下讓霞橫過，顯出「懸」 |
| **北** | 金閣、鏡湖池 | 台地一個（`shore-ground`）、丘一個（`far-bank`） | **衣笠山**是金閣後面的遠山（三座圓的山頭，低而寬）。鏡湖池四周是一圈**洲浜**（三到四片，池的北岸與西岸厚、東南薄），金閣站在北岸的洲浜上，倒影在池裡。池以外是留白的地與霞 |
| **南** | 東寺五重塔、金堂 | 丘三個 | 遠處一條低的**遠山**（兩三座，左上）。流水兩側各一條**岸**（現有的 `bank-left`、`bank-right` 改成扇貝狀的洲浜，不再是整塊的坡），塔與金堂站在岸上 |
| **右京** | 天龍寺大方丈、曹源池、借景 | 台地一個、丘兩個（`arashiyama`、`west-ridge`） | **嵐山**是曹源池後面的遠山（四座，右上，這一區的主角之一：借景），左上一小段**龜山**（低、淡）。曹源池四周是**洲浜**，大方丈前面一條**岸** |
| **西京** | 桂離宮書院、月見台、池庭 | 台地一個 | 沒有山。池庭四周是**洲浜**（四到五片，順著雁行的書院前緣走），月見台從岸上挑出水面。書院後面是霞與留白 |
| **山科** | 毘沙門堂的山門、石階、本殿、楓 | 台地一個、丘一個（`mountain`） | 本殿後面一座**遠山**（三座山頭）。石階兩側各一條窄的**岸**往上收，表現「登」。山門前是留白 |
| **上京** | 紫宸殿、南庭、回廊 | 台地一個（`court-surround`） | 沒有山、沒有洲浜。回廊圍起來的南庭已經是銀的平目地；回廊外面只有地與**霞**（殿後、左右各一道），顯出御所的平與靜。拆掉台地後不補東西 |

構圖的度（比樣板第一輪寬鬆，寫實際數字就好）：洲浜、岸、山合計佔蓋面 15–35%；留白的地至少 40% 且連通；任何輪廓不能有超過 30 單位的直線（山的圓弧不算）；每區的片與山的形彼此不同（`node scripts/plate-doha-similar.mjs` 要過）。

## 4. 驗收（每批）

**先拍修前。**

- 每區：不放大的日與夜各一張（修前修後並排）；放大兩倍看山一張、看岸或洲浜一張，目標在畫面中央（`PLATE_LIGHT` 把光移開）。放 `.shots/nine/<區>/`。
- 報告裡每區一張表：每座山、每片岸的理由（它襯托什麼）；實際的佔比數字（`node scripts/plate-doha-measure.mjs`）。
- `PLATE_TONE=1`：地、濃梨子地、圖案三層的順序與差距和樣板兩區相當（地 27–40、濃梨子地 46–60、圖案 50 以上且比濃梨子地亮或相當）。
- 穿插 `node scripts/plate-clip.mjs <out.json>` 為 0；相似度通過；切金佔比不高於改之前。
- 四項驗收；這一批的區的降級圖重拍（其餘還原）。
- 效能：375×812、`PLATE_CPU=4`，換到這一批的區的最長幀不比改之前多 10% 以上；烘焙時間每區不比改之前多 60 ms。
- 自審三輪以內。每區問：「山是不是一個完整的山體、岸的每一片為什麼在這裡、地標是不是比以前更突出、有沒有哪兩片看起來一樣、有沒有又把東西做扁」。答不出來的拿掉。
