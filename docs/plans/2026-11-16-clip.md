## 1. 使用者的要求

使用者附了山科放大的截圖（工作樹裡的 `.shots/ref/user-yamashina-clip.png`）：楓樹躺平時，樹冠明顯被土坡切過去。指示：「樹物件躺平時很明顯穿插到丘了。全面修穿插問題。」

「穿插」在這裡指：兩個不該互相穿過的東西，在畫面上互相切開。包含部件穿進隆起的地、部件穿進另一個部件。

## 2. 已確認的事實（主席只讀程式查到的）

- 地有隆起：`groundY(p)`（`three-pack.js` 的 `GROUND_GLSL`）從柔高度貼圖取高度，土坡最高約 17 單位（`M_SWELL`）。
- 建築這類站立部件（`PART_MOTION_GLSL`）躺下時逐頂點貼著地：`gy = mix(groundY(q), groundY(vec2(q.x, foot)), upF)`。躺著時跟著地起伏，站起來才回到腳線的高度。
- **樹沒有這樣做**：`TREE_LIMB_MOTION_GLSL` 與 `TREE_STAMP_MOTION_GLSL` 整棵樹只取 `groundY(anchor)`，是一片剛性的平面。樹冠伸到土坡上方時，土坡就從樹中間穿出來。這是截圖裡的成因。
- 部件平常不是完全躺平：`STAND_REST = .14`（`parts.js`），游標停在上面約 400 ms 才站起來。所以「躺著」是預設姿態，大多數時間看到的都是它。
- `scripts/plate.test.mjs` 有一條測試 `three: tree motion shaders use anchor groundY`，把「樹取錨點高度」寫成斷言。這是先前某個決定留下的；改之前先用 `git log -S "groundY(anchor)"` 查當初為什麼這樣定，在報告裡寫出來。
- 十一區的盤都有樹（`trees.js` 的 `stampedPine`／`stampedMaple`／`stampedGinkgo`／`stampedCourtTree`）。

## 3. 目標

十一區、兩種姿態（平常躺著、被游標叫起來站著），畫面上沒有看得出來的穿插。

**要查的種類**（不限於此，查到別的也列）：

| 種類 | 例子 |
|---|---|
| 樹 × 隆起的地 | 截圖：山科的楓樹冠被土坡切開 |
| 樹 × 其他部件 | 躺著的樹冠蓋到建築的腳、岩、燈籠、另一棵樹；站著時樹冠穿進屋簷 |
| 樹上的東西 × 樹 | 鶯、樹上的珊瑚葉 |
| 站立部件 × 站立部件 | 屋簷互穿、鳥居的柱穿進坡 |
| 矮的立體部件 × 地 | 岩、狐、燈籠、向月台有沒有沉進地裡或浮在空中 |
| 霞 × 高的部件 | 霞是半透明、浮在地上 0.35 單位。高的部件穿過霞是原本的設計，**不算穿插**；只有霞的邊緣把部件切出硬線才算 |

## 4. 做法（建議，不是規定）

先做偵測，再修，修完用同一個偵測重跑。

1. **偵測工具**：一支可重跑的腳本，對每一區、每一個部件、兩種姿態，列出「誰穿進誰、最深幾單位」。怎麼做由你決定。兩個可行方向：在瀏覽器裡（dev 模式）讀出柔高度場和部件的幾何，在 CPU 上算；或加一個除錯渲染模式把穿插的像素標出來再統計。`scripts/plate-shot.mjs` 已經有 `PLATE_EVAL`（在頁面裡跑一段表達式並印出結果）和 `window.__kyotoPlateUniforms`（dev 才有）可以借用。
2. **樹貼地**：最直接的修法是讓樹和建築用同一種混合，躺著時逐頂點（或逐葉片）跟著地，站起來回到剛性。要注意葉片是有厚度、互相疊的（`offset`），貼地後疊的順序不能亂；樹幹是掃出來的管，貼地後不能扭曲。如果查到當初定成錨點高度有不能繞過的理由，停下來回報。
3. **其餘種類**：依偵測結果逐項處理。優先用幾何與著色器解決（貼地、抬高、縮短）。

## 5. 限制

- **構圖**：可以移動部件來避開穿插，但單一部件移動不超過 12 單位、不刪部件、不加部件。需要移更多或刪掉才能解的，不要做，列成提案（哪一區、哪個部件、為什麼、建議怎麼改）。
- 不加依賴。不改受保護檔案（`AGENTS.md` §2）。不動資料（`src/data/`）。
- 上一輪剛定的視覺不要改：作舊（`uAge`）、平嵌依輪廓裁切、銀的規則、環境光遮蔽。見 `docs/plans/2026-11-16-patina.md` §9。
- 明暗用光影做，不往表面混暗色；表面相接要有漸變（`docs/HANDOFF.md` §5）。
- 改著色器檔案不要用 `sed -i`：dev server 偵測不到，會量到舊的。用編輯工具，或用腳本整檔寫回。
- 不 commit、不 push、不切分支、不 stash、不再派子代理。
