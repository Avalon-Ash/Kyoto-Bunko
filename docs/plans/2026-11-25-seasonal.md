### 2.2 Schema 草案

```ts
export type IsoDate = string;            // 'YYYY-MM-DD'，Asia/Tokyo 的曆日，不帶時刻
export type ClockTime = string;          // 'HH:mm'，Asia/Tokyo
export const OCCURRENCE_STATUS = ['confirmed', 'tba', 'postponed', 'cancelled'] as const;
export type OccurrenceStatus = typeof OCCURRENCE_STATUS[number];
export const EVENT_KINDS = ['matsuri', 'rite', 'night_viewing', 'special_opening', 'market'] as const;

/** 活動與地點的關係只在這裡定義；kind:'spot' 的區、分區、市域一律由景點導出，不重複存 */
export type EventVenue =
  | { kind: 'spot'; spotId: string }
  | { kind: 'ward'; wardId: WardKey; municipalityId?: string }; // 無對應景點或跨區

export interface EventSchema {
  id: string;                  // 'EV-NNN'，穩定、退役不重編
  kind: typeof EVENT_KINDS[number];
  venues: EventVenue[];        // ≥1（五山送火、祇園祭跨區）
  usualMonths: number[];       // 慣例月份 1–12；季節由 seasons.ts 導出
  officialUrl: string;
}
export interface EventSession {
  start: IsoDate; end: IsoDate;          // 含頭含尾，可跨年
  weekdays?: number[];                   // 0–6，限定星期；省略＝每日
  except?: IsoDate[];                    // 排除日
  hours?: { open: ClockTime; close: ClockTime };
}
export interface EventOccurrence {
  eventId: string; year: number;         // year＝首場開始日的年
  status: OccurrenceStatus;
  sessions: EventSession[];              // 非連續場次＝多筆 session
  admission: 'free' | 'paid' | 'mixed' | 'unknown';
  reservation: 'none' | 'required' | 'unknown';
  source: { url: string; checkedOn: IsoDate };
}
export interface EventLocale { name: string; desc: string; organizer: string; note?: string }
```

### 2.3 狀態語意（只定義在一處）

| 狀態 | sessions | 進日期查詢結果 | 總表 |
|---|---|---|---|
| `confirmed` | ≥1 | 是 | 顯示日期 |
| `tba` | 必須空 | 否 | 顯示慣例月份＋「待公告」 |
| `postponed` | 新日期已公告才填 | 有 sessions 才進 | 標示 |
| `cancelled` | 可留原訂日期 | 否 | 標示，預設不列為可參加 |

狀態→行為的表放在 `seasonal-query.ts` 的 `STATUS_RULES`，UI 讀它，不自行分支。

### 2.4 查詢（`src/lib/seasonal-query.ts`）

| 函式 | 行為 |
|---|---|
| `tokyoToday(now)` | 用 `Intl.DateTimeFormat`（`timeZone:'Asia/Tokyo'`）取曆日 |
| `sessionDates(session)` | 展開實際日期：套 `weekdays`、扣 `except`；以 UTC 做日數運算，不受本機時區影響 |
| `validateRange(from, to)` | 日期無效或結束早於開始時回傳錯誤碼 |
| `queryRange(occs, from, to)` | 先判區間相交（start ≤ to 且 end ≥ from），再取實際日期的交集，依日期與 `hours.open` 排序 |
| `listSeason(events, occs, year, season)` | 冬＝當年 12 月到次年 2 月；`tba` 依 `usualMonths` 歸季 |
| `isStale(checkedOn, today)` | 用具名常數 `STALE_AFTER_DAYS` |

測試資料由檔內的工廠函式 `makeOccurrence(overrides)` 產生，不寫死真實活動名稱。

### 2.5 `validate_data.js` 要加的檢查（待核對現有結構）

| 級別 | 檢查 |
|---|---|
| ERROR | ID 格式或重複；schema 出現 `name`／`desc` 等文字欄；`spotId` 不存在；`wardId`／`municipalityId` 未登記；中日 locale 缺漏或孤立 |
| ERROR | 場次的 `eventId` 不存在；`(eventId, year)` 重複；`year` 和首場開始日不符 |
| ERROR | 日期不是真實曆日（含 2/29）；start > end；`except` 落在區間外；`weekdays` 超出 0–6；時刻格式錯 |
| ERROR | 狀態和 sessions 不符（依 2.3）；`source.url` 不是 https；`checkedOn` 無效 |
| WARN | 主檔活動在載入的年度沒有場次列；某筆 session 展開後為零天 |

查核過期不放進 validate，否則時間一過 CI 就會自己變紅。改由 `scripts/audit-events.ts` 出報告，頁面用 `isStale` 顯示提示。

兩份都標「提議」，使用者同意後由主席改「採用」。`## 證據` 裡還不存在的路徑等 P1 落地後才補，否則 `adr:check` 不過。

```markdown
# 0023 歲時記活動資料：主檔、年度場次與雙語內容分離

狀態：提議
日期：2026-11-25

## 背景

歲時記要收京都年中行事 40–60 項與每年的場次。舊頁 `seasonal.html` 把多個日期寫成顯示字串，無逐項來源，不能當年度資料。活動有跨區（五山送火）與市外（大津）的情況。

## 決定

- 活動是獨立資料領域，放 `src/data/events/`：主檔 `catalog.ts` 只存結構；年度場次一年一檔 `occurrences/<年>.ts`；名稱、描述、主辦者在 `locales/{zh,ja}.ts`。
- 活動 ID 為 `EV-NNN`，穩定、退役不重編。
- 活動與地點的關係只定義在主檔的 `venues`：掛景點 ID，或只掛區（可帶 `municipalityId`）。掛景點時，區、分區、市域由景點導出，不另存。
- 每筆場次必須有官方或主辦者來源網址與查核日；查不到就是 `tba`，不推測。
- UI 只經 `events/loader.ts` 取資料。不修改受保護檔，不新增景點型別或標籤。

## 放棄的做法

- 把活動寫成景點（`SpotSchema`）或標籤：要改受保護檔，且景點沒有年度與日期。
- 主檔與場次合成一檔：每年換年會改到穩定的主檔資料。
- 在活動上另存 `wardId` 與 `spotId` 兩者：同一事實兩處，會失步。

## 後果

- `validate_data.js` 檢查 ID、外鍵、locale 鏡射、來源欄位；每年新增一個場次檔即可換年。
- 沒有對應景點的活動只能掛區，頁面無法連到景點卡。
- 每年需人工複查 40–60 筆。

## 證據

- `docs/SEASONAL_PLAN.md`
- `docs/adr/0001-schema-locale-separation.md`、`docs/adr/0003-protected-metadata-files.md`
```

```markdown
# 0024 歲時記日期語意：東京曆日、場次展開與狀態規則

狀態：提議
日期：2026-11-25

## 背景

京都觀光協會的活動搜尋提醒起訖期間不代表每天舉辦。活動有跨年、週末限定、休止日與分段場次；使用者可能在日本以外的時區查詢。

## 決定

- 日期一律是 Asia/Tokyo 的曆日字串 `YYYY-MM-DD`，時刻是 `HH:mm`；資料層不存 `Date` 或時間戳。
- 一個場次由多筆 session 組成，各有起訖（含頭尾）、選填的星期限定、排除日與時段。非連續場次用多筆 session，不用一段連續日期代替。
- 日期判斷只在 `src/lib/seasonal-query.ts` 的純函式：先判區間相交，再展開實際日期取交集。
- 狀態四種：`confirmed`、`tba`、`postponed`、`cancelled`；各狀態是否進查詢結果由同檔的一張表決定，UI 讀表。
- 季節月份表只在 `src/data/events/seasons.ts`；冬季跨年。

## 放棄的做法

- 單一 `date` 加顯示字串（舊頁做法）：無法查詢。
- 引入日期函式庫或 RRULE：規模 40–60 筆，內建 `Intl` 與 UTC 日數運算足夠。
- 用瀏覽器本機時區算「今天」：海外使用者會差一天。

## 後果

- `src/lib/seasonal-query.test.ts` 守跨年、閏日、排除日、非連續場次與狀態。
- 查核過期的判斷依賴當天日期，不放進 `validate_data.js`。
- 每月固定日的活動要逐日或逐段登錄。

## 證據

- `docs/SEASONAL_PLAN.md`（使用流程、資料測試、研究來源）
- `docs/adr/0014-behavior-tests-and-scope-fences.md`
```
