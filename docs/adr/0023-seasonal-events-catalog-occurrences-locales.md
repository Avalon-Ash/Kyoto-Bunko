# 0023 歲時記活動資料：主檔、年度場次與雙語內容分離

狀態：採用
日期：2026-11-25

## 背景

歲時記要收京都年中行事 40–60 項與每年的場次（使用者 2026-11-25：文庫的十一區＋大津、精選 40–60 項、第一版載 2027 年、入口是首頁的第四個檢索模式）。舊頁把多個日期寫成顯示字串、沒有逐項來源，不能當年度資料（`docs/SEASONAL_PLAN.md`）。活動有跨區（五山送火）與市外（大津）的情況，也有沒有對應景點的活動。

## 決定

- 活動是獨立的資料領域，放 `src/data/events/`：主檔 `catalog.ts` 只存結構；年度場次一年一檔 `occurrences/<年>.ts`；名稱、描述、主辦者在 `locales/{zh,ja}.ts`（照 0001 的 schema／locale 分離）。
- 活動 ID 是 `EV-NNN`，穩定、退役不重編（照 0002 的景點 ID 規則）。
- 活動和地點的關係只定義在主檔的 `venues`：掛景點 ID，或只掛區（可帶 `municipalityId`）。掛景點時，區、分區、市域由景點導出，不另存。沒有對應景點的活動只掛區，不為活動新增景點（使用者 2026-11-25）。
- 每筆場次都有官方或主辦者的來源網址與查核日；查不到就是待公告，不推測。票價只存免費、收費、需預約，金額連官方頁（使用者 2026-11-25）。
- 畫面只經 `src/data/events/loader.ts` 取資料。不改受保護檔（0003），不新增景點類型或標籤。

## 放棄的做法

- 把活動寫成景點（`SpotSchema`）或標籤：要改受保護檔，景點也沒有年度與日期。
- 主檔與場次合成一檔：每年換年都會改到穩定的主檔。
- 活動同時存 `wardId` 與 `spotId`：同一件事寫兩處，會不同步。

## 後果

- `validate_data.js` 要檢查活動的 ID、外鍵、雙語鏡射與來源欄位；換年只要新增一個場次檔。
- 只掛區的活動在頁面上連不到景點卡。
- 每年要人工複查 40–60 筆；查核日超過 90 天，頁面顯示過期提示（使用者 2026-11-25）。
