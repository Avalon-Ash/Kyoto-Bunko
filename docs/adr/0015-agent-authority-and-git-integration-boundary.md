# 0015 主代理整合、Git 權限邊界與定調工作歸屬

狀態：採用
日期：2026-11-17

## 背景

本專案同時由主代理、子代理與外部 IDE 代理協作，須避免多人覆寫同一檔案、未授權提交推送及跨模型反覆返工。子代理不得執行 Git 操作與主代理整合規則建立於 2026-10-28（`AGENTS.md` §1、`docs/AGENT_EXECUTION_PLAN.md` §4），定調類視覺工作歸主代理執行的「動手原則」與架構決策寫 ADR 之規則於 2026-11-17 定案，本檔取最新定案日 2026-11-17。

## 決定

- **主從權限邊界**：主代理負責拆包、派工、審查、整合、驗收與 Git 操作。子代理僅能在派工單指定的絕對路徑與檔案範圍內工作，禁止執行 commit、push、merge、rebase、reset、stash、切換分支、刪除工作樹、私自安裝依賴或再派子代理；成果以未提交 diff 交主代理審查。
- **Git 授權與隔離**：主代理僅依使用者當次授權執行 commit、merge 或 push（合併 `main` 與 `push` 分開詢問，舊輪授權不延續）。同時最多 2 名子代理；同一檔案同時僅有一個寫入者，寫入範圍重疊時須由主代理預先建立獨立 git worktree 隔離，不假定工具自動隔離；其他代理不得寫入 Gemini 正在使用的 checkout 或共用其測試瀏覽器。
- **定調工作歸屬（動手原則）**：材質、著色器外觀、看截圖反覆調整等前後相依的定調工作由主代理直接執行；僅互不相依、具明確目標圖或數字驗收之任務外派子代理。連續兩包出現「看得出問題但不能動手」即停止派工收回主代理。
- **ADR 變更權限**：限制後續程式寫法的架構級決策須一決策一檔記錄於 `docs/adr/`，由 `npm run adr:check` 檢查；動結構前須先查閱，與「採用」ADR 衝突時停下回報；子代理除派工單指定外不自行新增或修改 ADR。

## 放棄的做法

- 將前後相依的盤面定調視覺工作全數外派實作子代理：九區四名子代理耗用約 99 萬 token 後仍因著色器調整權限分離而反覆返工，遂於 2026-11-17 改採動手原則（`docs/plans/2026-11-17-finish.md` §2、§2.1、`docs/HANDOFF.md` §4.1）。
- 複製 FFT 專案的自動化命令包裝器、hook 或建立 `.codex/config.toml` 覆寫使用者全域模型偏好：本專案維持文件合約與明確派工單，不宣稱存在未落地的自動阻擋機制（`docs/AGENT_EXECUTION_PLAN.md` §1–§2、§6）。

## 後果

- 所有進入主線的改動均經單一主代理審查、整合與四項驗收，防止併行覆寫與未授權遠端變更。
- 主代理承擔較高整合與定調操作成本；未落成自動化 hook 前，工作區與模型設定紀律仰賴派工單與審查落實。
