# 0020 鄰盒的預覽只畫背景已建好的區，沒好就淡出淡入

狀態：採用
日期：2026-11-20

## 背景

首頁換函時，盒列連同左右鄰盒的預覽圖一起滑（`study.js` 的 `changeCabinet`）。使用者 2026-11-20 回報「換文箱還是會卡一下」。量到換盤那一刻幾乎不卡，卡的是盒停穩約 0.35 秒後的一次 285–600 ms 長任務（`docs/plans/2026-11-20-next.md` N5）：畫鄰盒預覽圖（`snapshotNeighbours`）用的是一般的換區（`renderer.setMesh`），鄰區此時還沒預建（預建排在 900 ms 後），於是同步建了兩個區；而一般換區會改排預建與淘汰快取，連目前這一區都可能被丟掉再重建。使用者提議用過場遮住卡頓；主代理建議先拿掉卡頓，快速連換時再用淡出淡入，使用者同意（「照這樣改」）。

## 決定

- **預覽圖只畫已經好的鄰區**：`three-renderer.js` 的 `drawNeighbour(ward, …)` 只在鄰區已由預建（閒置時分段）建好、程式也編譯完（`compileAsync` 結束）時，把它暫時綁上場景畫一幀，再綁回本區；不碰快取、淘汰與預建排程。沒好就回 false，頁面等 `onReady`（鄰區編譯完時呼叫）再畫。
- **頁面不再為了預覽圖換區**：`study.js` 畫預覽圖只走 `renderer.drawNeighbour`。
- **預覽圖沒好就淡出淡入**：換函時鄰盒預覽圖還沒畫好（剛換完又換），盒子淡出、換盤、淡入，不滑；換盤若要同步建新區，發生在盒子淡出的時候。

## 放棄的做法

- 滑到邊緣時把盒面調暗、模糊來遮卡頓（使用者的提議）：卡頓發生在盒停穩之後，不在滑動途中；而且主執行緒卡住時，靠逐幀推的暗化也會停。改為拿掉卡頓本身，只在來不及預建時用淡出淡入遮。
- 把預建提前到換盤時同步做：等於把同一段卡頓搬到滑動結束那一刻。

## 後果

- 換函後的長任務 285–600 ms → 最多 77 ms（無頭 Chrome、首頁、連續 4 次，N5）。
- 每 0.7 秒連換：走淡出淡入，換盤時仍有 136–454 ms 的長任務（新區還沒預建完），發生在盒子淡出時。
- 預覽圖會晚一點出現（鄰區預建與編譯完之後）；在那之前拖曳只看到盒子本身。
