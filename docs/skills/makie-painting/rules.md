# 使用者定的設計規則

每條：規則 → 【原話】（或來源）→ 為什麼 → 怎麼用。日期是使用者說的那一天。標記見 [sources.md](sources.md)。

「為什麼」與「怎麼用」除非另標【原話】，都是主代理依原話寫的做法【解讀】；和使用者當次的話衝突時以當次為準。R17 整條是主代理從兩次更正歸納的。

### R1　明暗用光不用畫（2026-11-16）
- 【原話】「積汙成相目前不太優，太工整看起來很刻意突兀。該是光影效果就不要用畫的。你對照初音調度它都是有過度的。」
- 為什麼：往表面混暗色會出現均勻、有邊的環；初音的深度來自浮雕本身的受光與蒔暈。
- 怎麼用：要加深度時先用光照項（遮蔽、陰影、法線），不要「把顏色混向暗色」。遮蔽只減環境光，衰減沒有邊。
- 來源：記:plate-light-not-paint；案:patina 修訂。

### R2　表面相接都要漸變（2026-11-16）
- 同上一句的後半。物與地、金與銀、霞的邊、磨損的邊、研出的邊，都給過渡。
- 怎麼用：交圖前對照參考圖，找畫面上有沒有「一圈」或「一條」。

### R3　畫面上的東西是正視的畫（2026-11-16）
- 【原話】「妳前面有一版銳利的其實才是比較接近。因為你被視角騙了所以才越作越扁圓。初音的構圖是正視，我們是俯瞰。妳松就有對喔。我猜妳是被厚度騙了。」
- 為什麼：初音的畫面是正視構圖；參考照片上的輪廓是物件的立面，不是平面。
- 怎麼用：岩、樹、建築都畫成立面的側影，躺在面上（Kyoto 的做法是被叫起來時繞腳線站起）；浮雕厚度薄薄的就好；發現自己越做越扁、越圓、越像地形就停。
- 來源：記:plate-objects-are-elevation-pictures；案:doha §18。

### R4　形歸形、意歸意（2026-11-13）
- 【原話】「楓樹主體說真的很詭異……樹不像樹。妳可以利用切金銀在文箱面上作楓葉落滿地的樣子啊，類似形 意象的作法。」「都用類似手法精進物件意象，給蒔判斷要改就改。」
- 怎麼用：立體先做認得出的普通形（樹＝分叉樹幹加樹冠）；保不住的特徵（葉形、花瓣、水中月、足跡、燈光）改成平嵌的切金銀、青貝意象。這類美術取捨使用者授權主代理判斷後直接改，改完給圖。
- 來源：記:plate-form-vs-imagery。

### R5　初音調度是技法定標，不是構圖範本（2026-11-16）
- 【原話】「初音調度很多都是近景圖，有源氏物語的故事，我們是山水建築。所以這邊你設計。我主要會提初音調度是因為這是技術集大成的蒔繪作品。」「京塗代表應該是平安時代漆器，但那些我認為太中國風，所以採用江戶的初音調度。」
- 怎麼用：對初音的是技法、材質、表面的質感與過渡；構圖自己設計。年代語言定在江戶，不往平安靠。山水加建築的布局可看印籠（使用者建議）與室町硯箱（後者是【解讀】）。
- 來源：記:hatsune-is-technique-benchmark；案:doha §1、§13.2。

### R6　地最深；金粉大、濃密、色多（2026-11-16）
- 【原話】「最深的是地，這邊剛好三種過渡，濃梨地又不太同。」「初音調度用的金粉更大、濃密、色多。」
- 怎麼用：三層調子（techniques §3）。地的暗來自片間的漆，片本身是亮的多色金。
- 來源：案:ground-tone §1、§3；案:doha §13.1。

### R7　先分漆上、漆下（2026-11-16）
- 【原話】「會統一色相是真漆的性。不統一反而不對。差異會在蒔繪在上還在下。」並要主代理查溜塗、八雲塗。
- 【原話，更正】「研出，顧名思義就是埋在漆下的物件研磨到同一個表面。所以重點在微觀的邊緣是包在漆下。我那個平文櫛很明顯掉下來的空缺邊緣是內包的。」
- 怎麼用：techniques §1 的四類。做每一種材質先問它在哪一類。
- 來源：記:hatsune-is-technique-benchmark；案:coat §7。

### R8　銀維持淡；作舊以保存良好的傳世品為準（2026-11-16）
- 【原話】「全部維持淡，因為這是沒保養好的問題。」（對一件銀已氧化變黑、平文脫落的江戶櫛）
- 怎麼用：不做銀變黑、平文脫落、裂紋、剝落、缺角、綠鏽。初音是保存極好的傳世品：有歲月，沒有損傷。
- 來源：記:plate-review-ask-why；案:technique-stack §8；案:patina §1.3。

### R9　漆經年變透（2026-11-17）
- 【原話，大意】真漆、溜的特性，經年會越來越透，一開始是比較深的褐色，慢慢變得越來越淺和透亮；江戶的初音色相比較亮，除了金粉量差以外就是漆養好了。「我理解是這樣，你可以上網看一下。」
- 怎麼用：作舊讓漆變透變亮（底下的金更亮更黃），不是變褐變暗；表面的霧與光澤減弱另算。畫面太橙褐、不夠像初音時，先想「漆還不夠透」，再想金粉量。年代可以做成參數（techniques §5）。
- 來源：記:urushi-clears-with-age；案:finish §15。

### R10　直書用漢數字（2026-11-17）
- 【原話】「你文字用直版就應該用大寫漢字／中文。」（看到直書的「漆齡 387 年」）
- 怎麼用：直書的文字裡數字寫成漢字（三百八十七），字與數字之間不留空格；橫書的介面照舊用阿拉伯數字。「大寫」解讀成用漢字寫數字（一二三），不是壹貳參【解讀】；使用者要壹貳參再改。
- 來源：記:vertical-text-chinese-numerals。

### R11　小景依附於物；主設計是該地特色（2026-11-14、11-16）
- 【原話】「地現在是無差別亂塞，把原來的物、形意破壞了。」（11/14，撤回隨機填隙）「主設計都是該區特色。你想你是日本人會想看到什麼。」（11/16）
- 怎麼用：每個小景掛在一個物上、說得出它屬於誰、在講什麼，寫進構圖資料；少而準；遠景與雲依各地地景個別設計，不用共用的生成器；選該地公認的名物，不用通用裝飾。
- 來源：MCP §7；記:plate-design-audience；案:roadmap §5a。

### R12　形逐片手寫、有手感（2026-11-16）
- 【原話】「形狀都是複製貼上不行，手感很重要。」
- 怎麼用：每一片地、每一座山、每一顆岩的輪廓逐一寫控制點，亂數只准用在微小的抖動；一群裡有大中小的節奏（最大至少是最小的三倍，【解讀】）；可以寫一支腳本把輪廓正規化後兩兩比相似度，當自我檢查。
- 來源：記:plate-review-ask-why；案:doha §10.3。

### R13　每樣東西答得出為什麼在這裡（2026-11-16）
- 【原話】「一眼可見問題，岩放在這些位子完全不合邏輯。你自己看不應該就放過喔。尤其右上角那顆最明顯不合理。」
- 怎麼用：交圖前逐群放大，對每個物件問「為什麼在這裡、尺度對不對、腳有沒有接地」；說不出理由的拿掉。派工單要寫物件「為什麼會在那裡」的規則，不只寫「放在哪」。
- 來源：記:plate-review-ask-why；案:doha §10、§10.5。

### R14　遠山是定型的肉合研出（2026-11-16）
- 【原話】「另外伏見的山體不應該是切碎的。你去看其他作品參考。」「遠山蒔繪是一種專門技法，呈現很一致。你可以關鍵字去找。」「對，所以要用肉合研出方式處理，給你看我收藏。」「遠山上不用畫樹啦，我這件朧若松山水裏鶴蒔繪盃是明治時期的物件，風格不一樣。」
- 怎麼用：techniques §4.2。
- 來源：案:doha §10.6–10.9；記:plate-review-ask-why。

### R15　大面積用梨子地、平目地；切金只做點睛（2026-11-16）
- 【原話】「上京那整面貼銀需要紋理細節，不然真的很突兀。」「高台丘這類大面積的你要就用刑部地，不應該整面菱形切金。就我所知日本沒有這樣用的技法。菱形切金銀都是畫龍點睛的光影用法。」「詳細研究蒔繪技法堆疊方式吧。」
- 怎麼用：techniques §2、§4.4、§4.5。
- 來源：案:technique-stack §1、§2。

### R16　屋面是蒔的，不是貼的（2026-11-16）
- 【原話】「建築的屋簷，你看起來是整片貼金。正確應該是用蒔繪方式處理，貼金都是小部分，且木胎貼金不會是完全的平整，金箔會透出木紋裡。」
- 怎麼用：techniques §4.7。
- 來源：案:roof-makie §1–§2。

### R17　看參考圖：先分技法與意匠、年代；再分經年與損傷（2026-11-16）
- 由 R8、R14 兩次更正歸納。使用者的江戶到昭和收藏可以直接請他拍照當參考，比網路上找的清楚；年代沒問過的，用之前先問。
- 怎麼用：明治、昭和的物件只取技法（例：一件明治盃只取山體的肉合研出）；保存不良的樣子不當成「舊」。不確定時多看幾件，不要只憑一張圖推論。
- 來源：記:plate-review-ask-why；記:user-lacquer-collection-album；案:doha §10.9、§12。

### R18　不做耦合（2026-11-17）
- 【原話】「你提到了耦合魔法數字 XD，這我不是三令五申禁止架構做耦合嗎？」「我能做 ECS＋SSOT 就會這樣做，因為對 AI 來說長期維護最友善。」
- 怎麼用：每種材質的性質（漆上漆下、套不套疏密、齊不齊平、包漿類別、銀要不要保持淡、粉從哪裡來）集中在一張表，畫法讀表；不在多處用編號或字串分支各判一次。數值要有名字並寫明依賴誰。已有的耦合先回報、先提案再解。
- 來源：記:no-coupling-no-magic-numbers；全域合約「架構」。
